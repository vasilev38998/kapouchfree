# Vibe

Прототип социальной сети с адаптивной лентой и входом/регистрацией по номеру телефона через одноразовый SMS-код.

## Что уже есть

- адаптивная лента Vibe для desktop и mobile;
- stories, публикации, лайки, подписки, поиск и тёмная тема;
- экран входа и регистрации по номеру телефона;
- одноразовый 6-значный код с временем жизни 5 минут;
- повторная отправка не чаще одного раза в 60 секунд;
- ограничение попыток проверки кода;
- базовый rate limit отправки SMS по IP;
- серверная интеграция с SMS.RU;
- HttpOnly session cookie после успешного входа.

## Локальный запуск

Нужен Node.js 20 или новее.

```bash
npm start
```

После запуска откройте `http://localhost:3000`.

Если `SMSRU_API_ID` не задан, приложение работает в режиме разработки: SMS фактически не отправляется, а код входа печатается в консоль сервера.

## Подключение SMS.RU

1. Зарегистрируйте аккаунт на SMS.RU и получите `api_id`.
2. Скопируйте `.env.example` в настройки окружения вашего хостинга.
3. Задайте секрет `SMSRU_API_ID` только на сервере.
4. Укажите публичный адрес сайта в `APP_ORIGIN`, например `https://vibe.example`.
5. В production задайте `NODE_ENV=production`, чтобы session cookie передавалась только по HTTPS.

Пример переменных:

```text
PORT=3000
APP_ORIGIN=https://vibe.example
NODE_ENV=production
SMSRU_API_ID=***
```

`SMSRU_API_ID` нельзя добавлять в клиентский JavaScript или публиковать в репозитории.

## Текущая архитектура авторизации

Браузер вызывает только наши endpoints `/api/auth/*`. Сервер генерирует код, хранит только его SHA-256 хеш, отправляет SMS через SMS.RU и после подтверждения создаёт HttpOnly cookie-сессию. API-ключ SMS.RU остаётся на сервере.

Сейчас OTP и сессии хранятся в памяти процесса — это подход для прототипа. Следующий backend-этап: PostgreSQL для пользователей и контента + Redis/аналог для OTP, сессий и rate limiting. Перед публичным запуском также нужно подключить CAPTCHA/anti-bot на выдачу SMS-кода.
